# P2–P6: repo moves

> Written by: Claude

> **State:** plan, not started, 2026-11-04. Phases P2–P6 of [MULTI-REPO-PLAN.md](MULTI-REPO-PLAN.md). Each move starts
> only when its in-tree rows in [P1-IN-TREE.md](P1-IN-TREE.md) are done and P0 is done.

## The standard move

Every repo moves the same way:

1. **Freeze.** Announce the move to the singleplayer lanes and pause commits to the moving paths. Record the
   singleplayer SHA.
2. **Bootstrap.** Run the P0.4 script to create `project-wildshard/<repo>` (private) with those paths at that SHA. The
   first commit names the SHA and the paths (J12).
3. **Binaries.** Large binaries in the moved paths go to R2 (`art` bucket) and are replaced by hash references (J13).
   The size-cap check runs in the new repo's CI from its first commit.
4. **Green.** The new repo's CI passes: build, tests, lint.
5. **Release.** If the repo is a dependency, cut `v0.1.0` with the P0.5 release script.
6. **Switch.** Singleplayer replaces the moved paths with the git dependency (or the deploy), and CI passes.
7. **Delete.** Remove the moved paths from singleplayer in one commit that names the new repo and tag.
8. **Unfreeze.** Record the move in [STATE.md](STATE.md).

**Rollback.** Until step 7, singleplayer still holds everything, so a failed move costs nothing: drop the new repo.

  cooks first-party shards for the standalone deploy.
