# Vite and Vitest temp files stay in ./tmp

Jake, 2026-11-09: "we are abusing tmp and need to stop". Vitest 5 writes
each transformed module under a 21-character folder in $TMPDIR, and a
killed run never removes it. macOS empties $TMPDIR at boot, before
login, and the boot hangs when it holds many files.

Every Vite and Vitest config here lists viteTmpRoot() from
scripts/vite-tmp.mjs, a byte-identical copy of repo-kit's. It roots the
run in tmp/vitest/<pid>, removes it when Vitest closes, and starts a
janitor at most every ten minutes. The janitor removes dead runs' folders
and the idle Vitest folders already in $TMPDIR. repo-kit's
test/tooling/vite-tmp-coverage.test.mjs fails when a config skips it or
the copy drifts. Meta plan: docs/plans/TEMP-HYGIENE-PLAN.md.

The same day the shared copy was made lint-clean for engine's strictest
rules (dot notation, import.meta paths, property signatures); behaviour
is unchanged.
